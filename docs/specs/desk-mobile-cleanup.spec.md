# Desk: works on a phone, markdown everywhere, one UI kit, one definition per type

Status: the milestone's spec, run by autopilot. This copy is kept in sync
with each slice (R18); narrowed requirements and requirements without an
issue go into the [Steering log](#steering-log).

## Goal

1. Every Desk page works on a phone: no sideways scrolling, nothing that only
   exists on wide screens, controls a thumb can hit.
2. Text written by agents and people renders as markdown wherever it is shown.
3. The Desk has one small UI kit, so controls behave and look the same and
   scoped CSS stops redefining them.
4. The task page is reorganised around what the owner wants to know first.
5. A type, a component and a class are defined once. What is outdated is gone.

## Decisions (locked)

1. **Slices, no big bang.** Each leaves the Desk working.
2. **Nuxt UI in the existing Vite app.** `@nuxt/ui` 4 (MIT) with its Vite
   plugin, `<UApp>` at the root and Tailwind 4. Not the Nuxt framework: the app
   stays a Vite SPA embedded in the Go binary. Imports are explicit
   (`autoImport: false`, `components: false`), because `npm run build` runs
   `vue-tsc` before Vite and the generated `.d.ts` files would not exist yet.
3. **One kit.** No PrimeVue, no Vuetify. Views use Nuxt UI components and
   Tailwind utilities. `web/src/ui/` holds only what Nuxt UI lacks (R4). A
   migrated view drops its scoped CSS, except what utilities cannot express.
4. **Sheets are `USlideover`, dialogs `UModal`.** `UDrawer` is not used: its
   `vaul-vue` dependency is unmaintained. Close by scrim, button, Escape and
   browser back. No swipe gestures.
5. **Bundle budget:** initial JS plus CSS at most 250 kB gzipped (52 kB today),
   views lazy-loaded by route, checked in CI. The first slice records the real
   figure; the cap drops to that plus 30 % if that is lower. If the kit breaks
   the cap, stop and report instead of raising it.
6. **`markdown.ts` stays the only renderer.** No `v-html`, no markdown-it, no
   streaming renderer. One component `Markdown` with two modes: `block`, and
   `inline`, which keeps strong, emphasis and code, shows links as their label
   (the rows are links already), drops block markup and folds newlines.
7. **What gets markdown.** Text written by an agent or a person, at the
   Background's lists: block for the first, inline for the second. Machine
   strings (condition messages, exit reasons, API errors) and thinking lines
   stay plain.
8. **Three widths:** phone under 760 px, tablet to 1180 px, desktop above. No
   other breakpoints.
9. **Phone navigation:** a bottom bar with Inbox (with its count), Overview,
   Projects (opens the rail as a sheet) and Research (with the feature on). The
   rail stays as it is on desktop.
10. **Context panel below 1180 px:** a *Context* button, with the Needs-you
    count, opens the same content in a sheet.
11. **Task page:** a header (title, stage, links, one status line), then tabs
    by `?tab=`: *Overview* (last run's summary first, questions, review, CI,
    plan, autopilot), *Chat* (chat and conversation), *Live*, *Calls*,
    *Details* (facts, pod, conditions). Questions waiting for an answer put a
    count on *Overview*. `#live-transcript` still opens *Live*. The issue page
    gets this through `TaskBody`.
12. **Tables on phones** stack each row as label and value. Comparison tables
    in Spend may scroll inside their own container, the page never does.
13. **Touch.** On phones: hit areas of at least 44 px, inputs at 16 px, `dvh`
    and safe-area insets, the composer stays above the keyboard. Truncated text
    opens on tap. `title` only for what is also readable elsewhere.
14. **One definition per type.** A view struct exists only when it differs from
    the store type by composition or by what it hides. Field-for-field pairs
    become one Go struct with JSON tags; a `Money` JSON type carries the
    cost-as-string difference. Every response is a named struct, generated by
    tygo.
15. **One client.** One function per route in `web/src/client.ts` with
    generated types. No `get<T>` outside it.
16. **Store stays hand-written SQL on pgx.** Static queries move from positional
    `Scan` to `pgx.RowToStructByName`. Spend's composed SQL stays. No ORM, no
    sqlc.
17. **Merge:** one composer, one prompt card with a compact variant, one note
    thread, one milestone row grid. Old redirects go.
18. **The CSP does not change** (`internal/ui/server.go:263`: `style-src 'self'`,
    `connect-src 'self'`, no `unsafe-inline`). Nuxt UI's colour plugin injects a
    `<style>` through `useHead`, which this policy refuses, so the `--ui-color-*`
    and `--ui-*` variables are defined statically in the CSS and the plugin is
    left out. If it cannot be left out, the Go server allows the exact hash of
    that style, computed at build time.
19. **No runtime fetches.** Icons come from an installed `@iconify-json/lucide`
    with `icon.clientBundle` (`scan` plus a list for dynamic names), so the
    Iconify API is never called. Fonts stay system fonts (Nuxt UI's font
    handling off).
20. **Tokens.** The palette of `style.css` stays and is mapped to Nuxt UI's
    `--ui-bg*`, `--ui-text*` and `--ui-border*`. Light and dark follow the
    system as today, no toggle; the values move to `:root` and `.dark`.
21. **Layers first.** Unlayered CSS beats Tailwind's layers, so the bare element
    rules of `style.css` (`a`, `h1` to `h3`, `code`, …) move into `@layer base`
    before the first Nuxt UI component ships.

## Constraints

- Go and web changes are separate slices. Groundwork comes first.
- The default budget is under 50 production lines per MR; split by requirement
  and by view. Moving one view to Nuxt UI may exceed it, since its markup and
  CSS move together: one view per MR.
- A decision that narrows a requirement opens a follow-up issue at that moment.
- Every R has an issue, or a line in the steering log saying why not.
- UI MRs link R1's screenshots at phone and desktop width.
- `make ui`, `make ts-types` and the `drift` job stay green. No `v-html` or
  `innerHTML`.
- Agent text stays untrusted: markdown without HTML, `safeURL` for links.
- System prompts stay unchanged (prompt cache).
- The milestone "release when it makes sense, and say why" runs first and adds
  release rows to `MilestoneIssues.vue`. Keep them when moving that view.

## Non-goals

- GraphQL. One client, 32 routes shaped per page, and the duplication sits
  between store, view and TS, which a schema would add to rather than remove.
  It would also need dataloaders to keep "a fixed number of queries" and move
  per-project authorisation into each resolver.
- Removing `Run.DeferredUntil` and `UsageLimits`: the runner writes and reads
  them (`runner.go:521,754,759`). They are not legacy.
- Dropping `legacyCostUSD`: it covers rows within history retention.
- Syntax highlighting, swipe gestures, PWA, offline, push, a theme toggle.
- New Desk features or API behaviour.
